# M3c 话题/分类页 实现计划

> 控制器直实现(subagent 基础设施不稳),逐任务 TDD + 验证 + 独立提交。完成后 Phase 1 收尾。

**Goal:** 采集时捕获 GitHub topics → 存入 `topics`/`repository_topics` → 暴露 `GET /api/v1/topics`(话题 + 仓库数)与 `GET /api/v1/topics/{slug}`(该话题下仓库,按 stars 分页),仓库详情含话题;前端话题列表页 + 话题详情页 + 详情页话题标签。

**Architecture:** 迁移 0004 建两表;`store.Repository` 加瞬时字段 `Topics []string`(来自 GitHub API,非 repositories 列);github 的 search/fetch 解析 `topics`;`store.SetRepositoryTopics` 在事务里 upsert 话题 + 重置某仓库的话题关联;`ingest` 在 discovery/submissions upsert 仓库后同步话题;新 store 读方法供 API;前端加页面/路由/client。

**Tech Stack:** Go 标准库 · React/TS · Vitest。无新增依赖。

> **依赖:** M0–M3b 在 `main`。GitHub REST 仓库/搜索响应默认含 `topics` 数组(`Accept: application/vnd.github+json`,已设)。离线:`GOPROXY=off go test ./cmd/... ./internal/...`。

## Task 1: store — 话题表 + 读写方法

**Files:** `internal/store/migrations/0004_topics.sql`、`internal/store/topic.go`、`internal/store/topic_test.go`

迁移:
```sql
CREATE TABLE topics (
    id   INTEGER PRIMARY KEY,
    slug TEXT NOT NULL UNIQUE,
    name TEXT NOT NULL
);
CREATE TABLE repository_topics (
    repository_id INTEGER NOT NULL REFERENCES repositories(id),
    topic_id      INTEGER NOT NULL REFERENCES topics(id),
    PRIMARY KEY (repository_id, topic_id)
);
CREATE INDEX idx_repo_topics_topic ON repository_topics(topic_id);
```

store 方法(topic.go):
- `SetRepositoryTopics(repoID int64, topics []string) error` — 事务:对每个 topic `INSERT OR IGNORE INTO topics(slug,name)` 再取 id;`DELETE FROM repository_topics WHERE repository_id=?` 后重新插入关联。slug=name=topic 原串(GitHub topics 已规范化为小写连字符)。
- `GetRepositoryTopics(repoID int64) ([]string, error)` — 该仓库的话题 slug,按 slug 升序。
- `TopicCount{Slug,Name string; Count int}` + `ListTopics() ([]TopicCount, error)` — JOIN 统计各话题仓库数,按数量降序、slug 升序。
- `RepositoriesByTopic(slug string, limit, offset int) ([]Repository, error)` + `CountRepositoriesByTopic(slug string) (int, error)` — 该话题下活跃仓库,按 stars 降序分页(复用 `repoSelectColumns`,JOIN repository_topics + topics)。

测试:set→get 往返;重设覆盖(旧关联清除);ListTopics 计数与排序;RepositoriesByTopic 过滤 + stars 排序 + 分页。
