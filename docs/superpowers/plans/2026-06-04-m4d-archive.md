# M4d Trending History Archive 实现计划

> 控制器直实现,逐任务 TDD + 验证 + 独立提交。Phase 2 增量(收尾)。

**Goal:** 历史归档:浏览在某 period 榜单上**曾经上过榜**的所有仓库,按上榜次数聚合 —— `GET /api/v1/archive` + 前端 `/archive` 页。

**Architecture:** store 新增 `ListArchive`/`CountArchive`(对 `trending_rankings GROUP BY repository_id` 的 live 聚合,镜像 `ListDevelopers`,复用 `repoColsR`)。api 加只读分页端点(镜像 `/developers`)。前端加页面/导航。

> **依赖:** M0–M4c 在 `main`。复用 `repoColsR`、`validPeriods`、`atoiDefault`、前端 `PeriodTabs`/client/路由/导航。

## Task 1: store — ListArchive / CountArchive

**Files:** `internal/store/archive.go`、`internal/store/archive_test.go`

```go
type ArchiveEntry struct {
	Repo          Repository
	Appearances   int
	BestRank      int
	PeakStarDelta int
	FirstRanked   string
	LastRanked    string
}
```
- `ListArchive(period, limit, offset)`:`SELECT COUNT(*), MIN(tr.rank), MAX(tr.star_delta), MIN(tr.period_date), MAX(tr.period_date), `+repoColsR+` FROM trending_rankings tr JOIN repositories r ON r.id=tr.repository_id WHERE tr.period=? GROUP BY tr.repository_id ORDER BY COUNT(*) DESC, MIN(tr.rank), r.full_name LIMIT ? OFFSET ?`。扫描同 `ListRankings`(archived/active int→bool)。
- `CountArchive(period)`:`SELECT COUNT(DISTINCT repository_id) FROM trending_rankings WHERE period=?`。

测试:A 上 daily 两天(rank 3 then 1,delta 10 then 30)、B 上 daily 一天 + weekly 一天。断言:`CountArchive("daily")=2`;`ListArchive("daily")` A 在前(2 次、best=1、peak=30、first 2026-06-09、last 2026-06-10),B(1 次、best=2);period 隔离 `CountArchive("weekly")=1`。
